# Contexto del producto

## Problema

En una pequeña empresa, las tareas repetitivas pueden estar repartidas entre correo, teléfono, hojas de cálculo y sistemas internos. La persona que conoce el proceso no siempre tiene mediciones fiables ni sabe qué información hace falta para evaluar una posible mejora.

## Propuesta de valor

Una entrevista clara convierte la descripción del trabajo cotidiano en un resumen revisable. Con datos suficientes, el producto podrá mostrar carga de trabajo y oportunidades de mejora de forma trazable, sin ocultar supuestos ni presentar automatización como ahorro garantizado.

## Experiencia deseada

- Una pregunta principal por paso, con progreso y navegación atrás.
- Lenguaje comprensible para personas no técnicas.
- Respuestas como «No lo sé», «No aplica» y «Prefiero no responder».
- Revisión y edición de los datos antes de confirmar.
- Alternativa escrita siempre disponible, incluso cuando se incorpore voz.
- Estados de finalización y error que no afirmen operaciones que no ocurrieron.

## Confianza y privacidad

La procedencia y confirmación de cada dato deben conservarse. Si faltan datos esenciales o hay contradicciones, el resultado debe explicarlo. La demo no debe enviar datos a servicios externos.

## Sector y proceso de inicio

El primer caso de uso es una distribuidora mayorista pequeña y su proceso de recepción y gestión de pedidos recibidos por correo, teléfono o mensajería hasta que se registran y confirman.
